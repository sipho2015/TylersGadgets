# Tyler's Gadgets

Static electronics catalogue and repair website for Victoria Falls, Zimbabwe. Built with HTML, CSS and browser-native JavaScript modules. All purchases, quotations, repairs and trade-ins are arranged through WhatsApp or email. No backend, database, account system, checkout or runtime dependencies.

## Run and build

- `npm.cmd start`: preview editable source at http://localhost:3000 (existing hash routes).
- `npm.cmd test`: run unit, rendering, data, image and static-build checks.
- `npm.cmd run build`: generate the production website in `dist/`.
- `npm.cmd run preview`: serve `dist/` at http://localhost:3000 after building.
- `npm.cmd run seo`: update source homepage metadata and robots.txt. Production metadata and sitemap are generated by `build`.

Node.js is required. No npm installation is needed to build or serve the site. Stop the preview with Ctrl+C.

## Vercel and public URLs

`vercel.json` configures the build command `npm run build` and output directory `dist`. Use Framework Preset **Other**. This replaces the earlier deployment instructions that served the project root with no build command.

The production hostname is resolved from `SITE_URL`, then `siteConfig.siteUrl`, then Vercel's `VERCEL_PROJECT_PRODUCTION_URL`. Vercel must expose its system environment variables (Project Settings > Environment Variables). See https://vercel.com/docs/environment-variables/system-environment-variables.

Until a hostname is known, local builds omit canonical links and the sitemap. No domain is guessed. On Vercel, the assigned production hostname supplies absolute metadata and sitemap URLs. Later, set `SITE_URL` to the confirmed HTTPS origin for the .co.zw or .com domain and redeploy. Use the same origin for social previews; do not enter only `vercel.app`, `.co.zw` or `.com`.

The build generates 76 HTML pages: home, catalogue/categories, repairs, gallery, about, five policies and 63 products. Products have paths such as `/product/iphone-15/`. Refreshing and opening direct links works on static hosting. Old `#product/iphone-15` and other hash links remain supported. Built pages contain readable content, local business/product structured data and product-specific social metadata without JavaScript. Filters, lists, enquiry forms and image viewers require JavaScript. WhatsApp and email links never send automatically.

Deploy the contents of `dist/` on other static hosts. They must serve directory index.html files. Hosting below a subdirectory is not supported; the generated site uses root-relative routes.

## Customer features

- 63 listings: 33 phones, four laptops, 26 accessories. Confirmed USD prices and all supplied product details are preserved.
- Combined search, category, phone-brand, condition and availability filters, clear filters, price and newest sorting.
- Product details, actual photo galleries, accessible image viewers, thumbnail keyboard navigation and touch swipe between available product images.
- Comparison for up to three products, with missing values marked Not specified and no invented specifications. Tables fit wider screens; smaller screens show stacked device cards without horizontal scrolling.
- Multi-product enquiry list with prepared WhatsApp/email messages; this does not reserve stock or create an order.
- Saved products and up to eight recently viewed products. All four browser lists store product IDs only, with no accounts or cloud sync. Blocked storage falls back to memory for the current visit. Clear controls remove stored selections.
- Optional repair and trade-in details generate messages, including preferred repair contact method. Forms are not stored. Customers attach photographs manually in WhatsApp or email.
- Ten dedicated local gallery photographs, category/brand filters and keyboard-operated image viewer.
- Existing delivery, policies, FAQ and business contact details, plus click-to-call and email actions.

## Content maintenance

| Content | File |
| --- | --- |
| Business details, payments, delivery, hours, public URL, testimonials | data/site-config.js |
| Products, confirmed prices/specs/condition/stock and repair names | data/products.js |
| Shared images, FAQs, gallery and approved repair examples | data/content.js |
| Customer policies, including browser storage disclosure | data/policies.js |
| Shared UI and styles | src/core/ |
| Individual page layouts and interactions | src/pages/ |

Keep product IDs and slugs stable. Unknown prices stay null and display Contact for Price. Never convert `legacyPrice` into USD automatically. Unknown stock displays Confirm Availability. Sold products cannot generate normal purchase enquiries. Boxed is a packaging attribute and never implies New. Empty optional sections are omitted.

Eighteen listings are clearly marked as references, with prices, stock, condition and specifications unconfirmed. The existing laptop/accessory prices await confirmation. Some general homepage/service/laptop imagery still uses Unsplash; local product photos remain unchanged. Replace general development imagery only with suitable, approved photographs.

## Optional verified content

- New arrivals: set `newArrival: true` explicitly or provide a valid `dateAdded`/`addedAt` ISO date within the last 30 days. Future/invalid dates do not qualify. Without qualifying products, the section is hidden.
- Offers: provide valid `originalPrice` (or `oldPrice`) and `promotionalPrice` (or `price`), with the promotional price below the original. Optional `promotionLabel` and `promotionExpiry` (ISO date or timestamp). Expired/invalid offers and sold products are excluded. Active prices are used on cards, details and enquiry messages.
- Testimonials: add authentic approved `{name, quote, rating?, date?}` records to `siteConfig.testimonials`. Only ratings from one to five are shown. The section is hidden while empty.
- Repair examples: add approved real `{model, repairType, before, after, description?}` records to `repairShowcases` in content.js. Hidden until both photos and required captions exist.
- Warranty periods, Sunday fees and unconfirmed specifications must be supplied by the business.

## Image preparation

Original photographs are preserved. Generated responsive WebP copies live in `assets/optimized/`; `src/core/image-manifest.js` maps originals to variants and dimensions. The browser chooses a suitable size. Below-the-fold images load lazily, and failed images have category fallbacks.

When adding/replacing photos, the site works with originals immediately. To refresh optimized copies, install development-only tooling into an ignored directory and run:

```powershell
npm.cmd install --prefix .verification/tools --no-save sharp@0.35.5
node scripts/optimize-images.mjs .verification/tools/node_modules/sharp/dist/index.mjs
npm.cmd run build
```

Commit the resulting optimized assets and manifest with the other changes when ready. Sharp is used only to prepare images; it is not a production dependency.

## Browser verification

For reproducible browser checks, start the production preview on port 3100 in one terminal:

```powershell
$env:PORT='3100'
npm.cmd run preview
```

In another terminal:

```powershell
npm.cmd install --prefix .verification/tools --no-save playwright lighthouse sharp@0.35.5
node scripts/verify-browser.mjs .verification/tools/node_modules/playwright/index.mjs
```

The script defaults to installed Chrome on Windows; set `CHROME_PATH` for another executable. It checks 320, 375, 430, 768, 1024 and 1440 pixel layouts, navigation, filters, comparison limits, saved lists, enquiries, repair/trade forms, gallery, direct URLs, refresh and no-JavaScript content. Reports/screenshots are written to ignored `.verification/` files.

Lighthouse can be measured separately with the installed CLI:

```powershell
$env:CHROME_PATH='C:/Program Files/Google/Chrome/Application/chrome.exe'
node .verification/tools/node_modules/lighthouse/cli/index.js http://localhost:3100/ --chrome-flags='--headless --no-sandbox' --output=json --output=html --output-path=.verification/lighthouse-home
```

Scores vary by hardware, network and hosting. Local measurements do not guarantee production scores. Verification results and remaining content requirements are recorded in ENHANCEMENT-REPORT.md.
